# 註解原則
以支援團隊協作（co-work）為目標。優先確保**可讀性**、**可維護性**與**可理解性**，再追求簡捷。

## 必要註解
- 覆蓋: class / function / closure / property / 結構單位 / 複雜邏輯 / Domain Knowhow / 計算式
- class: 用途 + 使用案例
- function: I/O（輸入/輸出格式）
- DECISION: 選 A 捨 B 時記錄取捨理由，防後人「優化回去」

## 補充情境
符合以下任一情況應補充註解
- 提升 可讀性 / 可維護性 / 理解性
- 加速新人或接手者上手
- 提升 Code Review 判讀效率

## 結構單位（branching statements / declare / action / step / code block）
- function 由多個結構單位組成（單行或多行）
- 過長邏輯需拆為子 function
- 每個結構單位必須註解：說明目的與行為
- 請不要編號

> 結構單位的註解用於**段落劃分**與**用途說明**，幫助閱讀者**快速辨識邏輯邊界**，對非英文母語的開發者尤其重要。
